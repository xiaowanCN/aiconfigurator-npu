# 2 系统架构与功能模块设计

> 本章描述 aiconfigurator-npu（AIConfigurator Ascend NPU 版）在 **default 模式**下的系统架构层级与功能模块划分。
>
> - 配图源文件：`2.1_系统架构_五层架构.drawio`、`2.2_功能模块.drawio`（可用 draw.io / VS Code drawio 插件打开编辑）
> - 术语约定：文中 "Qwen3.8" / `qwen_3_8_config.json` 指 **Qwen3-8B**（约 8B 参数的 dense 模型），下同。

## 2.1 系统架构

### 2.1.1 架构总览

aiconfigurator-npu 是一个 **静态配置搜索与性能估算系统**：不执行真实推理，而是通过「算子级性能数据库 + 模型算子图 + 多维配置枚举 + SLA 硬过滤 + Pareto 选型」的组合，在部署前给出满足 SLA 约束的最优并行/批次配置集。

系统在 default（聚合服务）模式下采用 **五层计算架构**，层层递进，自上而下完成从"用户输入"到"最优部署配置"的完整链路；底部为独立的输出层，负责结果落盘与部署配置生成。左侧为贯穿建模层的 **性能数据生产闭环**，支撑整个估算体系的数据供给。

> **架构图**：见 `2.1_系统架构_五层架构.drawio`

整体结构如下：

```
┌─────────────────────────────────────────────────────────────┐
│ L1 输入层    SLA / 模型 / 硬件 / 后端 / 预算 / 取数模式        │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ L2 建模层    PerfDatabase 性能库 · 模型算子图 · 算子集 · 后端   │←── 性能数据闭环
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ L3 搜索层    并行枚举 × batch 扫描 × ctx/tpot 网格 × OOM 裁剪  │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ L4 估算层    逐算子查库 → TTFT/TPOT → 吞吐 → 显存 → 功耗       │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ L5 选型层    SLA 硬过滤 → Pareto 前沿 → pick_default top-N    │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 输出层       CSV / PNG / exp_config.yaml / generator_config  │
└─────────────────────────────────────────────────────────────┘
```

### 2.1.2 五层职责详解

#### L1 输入层（Input Layer）

**职责**：接收原始输入——模型定义、硬件系统、推理后端、性能数据库选择、workload 与 SLA 约束、资源预算。

| 输入维度 | 来源 | 说明 |
|----------|------|------|
| SLA 约束 | `--isl` `--osl` `--ttft` `--tpot`（可选 `--request-latency` `--prefix`） | isl/osl 为输入/输出序列长度；ttft/tpot 为延迟上界（ms），作为搜索的**硬过滤条件**而非单点目标 |
| 模型定义 | `--model-path` | HF model id 或本地 `config.json`（如 `qwen_3_8_config.json`） |
| 硬件系统 | `--system` | 对应 `systems/{system}.yaml`，如 `ascend_910b.yaml`（64GiB HBM / 2TB/s / BF16 256TFLOPS / 8 die 节点） |
| 推理后端 | `--backend` `--backend-version` | 如 `vllm-ascend` + `0.18.0`，决定算子性能数据目录 |
| 资源预算 | `--total-gpus` `--top-n` | GPU 预算约束搜索空间；top-N 控制输出条数 |
| 取数模式 | `--database-mode` | `SILICON` / `HYBRID` / `EMPIRICAL` / `SOL`，控制性能估算的数据来源策略 |

**关键模块**：`cli/main.py`（参数解析）→ `sdk/task.py`（`TaskConfig` / `TaskContext` / `TaskConfigFactory` 配置叠层）。

配置叠层顺序：`base-common` → `agg-defaults` → `profile:*` → `yaml_patch` → `finalize`（按 `total_gpus` 裁剪），保证默认配置、用户覆盖、资源约束依次生效。

#### L2 建模层（Modeling Layer）

**职责**：把模型定义转换为可估算的算子图，绑定并行形状与量化模式；同时装配性能数据库与后端调度模型。

| 子模块 | 关键类 / 文件 | 职责 |
|--------|--------------|------|
| PerfDatabase 性能库 | `sdk/perf_database.py` | 按 `{system}/{backend}/{version}` 加载 gemm / attn / moe / nccl 等算子插值表，支持 1D/3D 线性插值 |
| 模型算子图 | `sdk/models.py`（`BaseModel` / `LLAMAModel` / `MOEModel` / `DeepSeek*` / `Qwen35Model`） | 将 HF config 分解为 context（prefill）与 generation（decode）两套算子序列 |
| 算子集 | `sdk/operations.py` | `GEMM` / `ContextAttention` / `GenerationAttention` / `CustomAllReduce` / `NCCL` / `MoE` / `MoEDispatch` 等原子算子 |
| Backend 步分解 | `sdk/backends/`（vllm / trtllm / sglang） | 后端调度步分解与指标公式（TTFT/TPOT/吞吐的计算口径） |

**模型建模流程**（以 Qwen3-8B 为例）：

1. `_parse_hf_config_json` 解析 `layers / hidden_size / num_heads / num_kv / intermediate_size / vocab`
2. 架构映射：`Qwen3ForCausalLM → LLAMA family`；Qwen3 系列附加 `use_qk_norm=True`
3. `get_model` 实例化 `LLAMAModel`，构建算子序列：
   `Embedding → add_norm → qkv_gemm → ContextAttention → proj_gemm → gate_ffn1 → act → ffn2 → logits_gemm`
4. 每个算子绑定 `(tp, pp, dp)` 并行形状与量化模式（gemm / kvcache / fmha / comm）

#### L3 搜索层（Search Layer）

**职责**：在合法空间内枚举候选配置点，形成 (并行, batch, ctx_tokens, tpot) 的多维搜索网格。

| 搜索维度 | 枚举方式 | 代码位置 |
|----------|----------|----------|
| 并行配置 | 五元组 `[tp, pp, dp, moe_tp, moe_ep]`，按 `num_gpu_per_worker` 与合法性约束过滤 | `sdk/utils.py:enumerate_parallel_config` |
| batch / concurrency | `1 .. 512` 非均匀网格 | `InferenceSession.find_best_agg_result_under_constraints` |
| ctx_tokens | chunked prefill 步粒度（启用时） | 同上 |
| tpot 网格 | `1..19` 步长 1，`20..295` 步长 5 | `TaskRunner.run_agg` |
| OOM 约束 | `weights/TP + activation + KV + HCCL ≤ HBM`，不满足则裁剪 | `inference_summary.py` |

**并行枚举规则**：
- 非 MoE 模型（Qwen3-8B）：`tp ∈ {1,2,4,8}, pp = dp = moe_tp = moe_ep = 1`，约束 `tp × pp ∈ num_gpu_list`
- MoE 模型（如 Qwen3-235B-A22B）：额外枚举 `dp / moe_tp / moe_ep`，约束 `dp × tp == moe_tp × moe_ep`；vllm-ascend 禁止 MoE-TP 与 MoE-EP 同时切分
- `--total-gpus 8` 对 `num_gpu_per_worker` 做预算裁剪

#### L4 估算层（Estimation Layer）

**职责**：对每个候选点计算绝对指标，与 SLA 约束对比。

| 估算项 | 计算口径 |
|--------|----------|
| 延迟 | 逐算子查性能库（实测插值或 SOL+经验系数）→ 按 backend 步分解累加 → **TTFT**（prefill）/ **TPOT**（decode） |
| 吞吐 | `seq/s`、`tokens/s`、`tokens/s/user`、`request_latency` |
| 显存 | `weights/TP + activation + KV cache + HCCL 开销 + reserved`，判定 OOM |
| 功耗 / 能耗 | `Σ(op energy) / Σ(op latency)`（性能库带 power 列时） |

**DatabaseMode 取数策略**（`--database-mode`）：

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| `SILICON` | 仅用实测数据插值，缺失直接报错 | 性能库完整时的最精确估算 |
| `HYBRID` | **有实测用实测，缺失回退 SOL × 经验系数** | 实测库不完整时的稳健选择（本设计默认推荐） |
| `EMPIRICAL` | 一律 SOL × 经验系数 | 无实测库时的快速估算 |
| `SOL` / `SOL_FULL` | 理论带宽/算力上限模型 | 上界分析与校准 |

**关键模块**：`sdk/inference_session.py`（`InferenceSession.find_best_agg_result_under_constraints`）。

#### L5 选型层（Selection Layer）

**职责**：从候选点集中筛选、排序、输出最优配置集。

选型流程：

1. **SLA 硬过滤**：`ttft ≤ target` 且 `tpot ≤ target`，剔除 OOM 点
2. **集群折算**：按 `total_gpus` 预算计算 `tokens/s/gpu_cluster`（可容纳的副本数 × 单副本吞吐）
3. **Pareto 前沿**：在 `(tokens/s/user, tokens/s/gpu_cluster)` 二维空间提取非支配点集
4. **pick_default**：固定 GPU 预算下最大化吞吐，按并行组去重，取 **top-N**（`--top-n`）
   （可选 `pick_load_match`：满足目标并发/请求率下最小化 GPU 数）

**关键模块**：`sdk/pareto_analysis.py`（`agg_pareto` / `get_pareto_front`）、`sdk/picking.py`（`pick_default`）。

#### 输出层（Output Layer）

**职责**：结果落盘与部署配置生成。独立于五层计算框架，不参与估算计算。

| 输出文件 | 内容 |
|----------|------|
| `best_config_topn.csv` | top-N 推荐配置表（并行/量化/延迟/吞吐/显存/功耗全维度） |
| `pareto.csv` | 完整 Pareto 前沿点集 |
| `pareto_frontier.png` | Pareto 散点图（tokens/s/gpu vs tokens/s/user） |
| `exp_config.yaml` | 可复现实验的 TaskConfig YAML |
| `top1../topN/generator_config.yaml` | 各推荐配置对应的部署生成配置 |
| backend artifacts | vLLM / dynamo 等后端可部署配置文件 |

**关键模块**：`cli/report_and_save.py`（`save_results`）、`generator/`（`task_config_to_generator_config` / `generate_backend_artifacts`）。

### 2.1.3 性能数据生产闭环

左侧纵向通路是支撑 L4 估算层的 **数据生产闭环**，独立于在线搜索链路，离线运行：

```
collector/ 真机算子采集  →  tools/ 格式转换与校验  →  systems/data/ 算子性能数据库
   (GEMM·Attn·MoE·MLA)        (convert_to_aiconfigurator)      (gemm/attn/moe/nccl 表)
                                                                   │
                                                                   ▼
                                                          L2 PerfDatabase 灌库
```

- **collector/**：在真实 Ascend 910B 上运行微基准（GEMM、Attention、MoE、MLA、HCCL 集合通信），采集算子延迟/功耗
- **tools/**：把原始采集数据转换为 AIConfigurator 插值表格式（`*_perf.txt` / `*.csv`）
- **systems/data/**：按 `{system}/{backend}/{version}` 组织的算子性能表，由 `PerfDatabase` 加载

这保证了性能库可以随硬件/后端版本演进持续更新，而无需改动估算与搜索逻辑。

### 2.1.4 代码包结构与层的映射

```
src/aiconfigurator_npu/
├── cli/          →  L1 输入层 + 输出层（参数解析、结果落盘、部署生成入口）
│   ├── main.py            参数解析 / TaskConfig 构建 / 实验编排
│   ├── report_and_save.py 结果落盘
│   └── utils.py           实验后处理（top-N 选择）
├── sdk/          →  L2 建模 + L3 搜索 + L4 估算 + L5 选型
│   ├── task.py            TaskConfig / TaskConfigFactory / TaskRunner
│   ├── models.py          模型算子图（L2）
│   ├── operations.py      算子集（L2）
│   ├── perf_database.py   性能库（L2）
│   ├── backends/          后端步分解（L2）
│   ├── inference_session.py  约束搜索（L3+L4）
│   ├── pareto_analysis.py    Pareto 提取（L5）
│   └── picking.py            选型策略（L5）
├── generator/    →  输出层（部署配置生成）
├── systems/      →  数据层（硬件规格 YAML + 算子性能表）
└── collector/    →  性能数据生产闭环（真机采集）
```

## 2.2 功能模块

### 2.2.1 功能模块总览

系统在 default 模式下划分为 **六大功能模块**，与执行流程一一对应。

> **功能模块图**：见 `2.2_功能模块.drawio`

```
命令输入  →  M1 CLI 参数解析  →  M2 模型解析与建模  →  M3 并行配置拆解
                                                        │
                                                        ▼
输出物  ←  M6 结果输出与部署生成  ←  M5 Pareto 选型  ←  M4 性能估算引擎
```

| 模块 | 名称 | 核心职责 | 代码位置 |
|------|------|----------|----------|
| M1 | CLI 参数解析 | 命令解析、参数校验、TaskConfig 构建 | `cli/main.py`, `sdk/task.py` |
| M2 | 模型解析与建模 | HF config 解析、架构映射、算子图构建 | `sdk/utils.py`, `sdk/models.py` |
| M3 | 并行配置拆解 | 并行五元组枚举、合法性校验、预算裁剪 | `sdk/utils.py` |
| M4 | 性能估算引擎 | 算子查库插值、TTFT/TPOT/吞吐/显存/功耗估算 | `sdk/perf_database.py`, `sdk/inference_session.py` |
| M5 | Pareto 选型 | 候选扫描、SLA 过滤、前沿提取、top-N 选型 | `sdk/pareto_analysis.py`, `sdk/picking.py` |
| M6 | 结果输出与部署生成 | 结果落盘、部署配置生成 | `cli/report_and_save.py`, `generator/` |

### 2.2.2 模块详细说明

#### M1 CLI 参数解析

| 功能点 | 说明 |
|--------|------|
| default / disagg 子命令注册 | `aic-npu default`（聚合服务）与 `aic-npu disagg`（PD 分离）双模式 |
| 参数校验 | `--total-gpus` 必须 ≥1 且被 `--sys-tp-size` 整除；`total-gpus < isl` 时告警 |
| TaskConfig 构建 | 将 CLI 参数封装为 `TaskConfig` / `TaskContext` |
| 配置叠层工厂 | `base-common` → `agg-defaults` → `profile:*` → `yaml_patch` → `finalize`（按 total-gpus 裁剪） |

#### M2 模型解析与建模

| 功能点 | 说明 |
|--------|------|
| HF config.json 解析 | 抽取 `num_hidden_layers / hidden_size / num_attention_heads / num_key_value_heads / intermediate_size / vocab_size` |
| 架构映射 | `Qwen3ForCausalLM → LLAMA` family（`Qwen3MoeForCausalLM → MOE`） |
| QK-Norm 标记 | Qwen3 系列自动附加 `use_qk_norm=True`，影响 Attention 算子建模 |
| LLAMAModel 算子图构建 | 生成 context（prefill）与 generation（decode）两套算子序列：<br>`Embedding → QKV-GEMM → Attention → Proj-GEMM → FFN(2×GEMM) → Logits-GEMM` |

**Qwen3-8B 模型规格**（`qwen_3_8_config.json`）：

| 参数 | 值 |
|------|-----|
| 架构 | Qwen3ForCausalLM（dense，非 MoE） |
| 层数 | 36 |
| hidden_size | 4096 |
| attention heads | 32（GQA，kv_heads=8） |
| intermediate_size | 12288 |
| 参数量 | ~8B |

#### M3 并行配置拆解

| 功能点 | 说明 |
|--------|------|
| 五元组 | `[tp, pp, dp, moe_tp, moe_ep]`（张量并行 / 流水并行 / 数据并行 / MoE 张量并行 / MoE 专家并行） |
| Qwen3-8B 非 MoE 拆解 | `TP ∈ {1, 2, 4, 8}`，`PP = DP = moe_tp = moe_ep = 1` |
| 合法性校验 | `num_attention_heads % tp == 0`；`num_layers % pp == 0`（仅告警） |
| 预算裁剪 | `--total-gpus 8` 裁剪 `num_gpu_per_worker ∈ {1, 2, 4, 8}` |

**搜索空间规模**（Qwen3-8B + 8 卡）：4 组并行配置 × batch 1-512 × tpot 网格（约 70 点）≈ **数千候选点**。

#### M4 性能估算引擎

| 功能点 | 说明 |
|--------|------|
| DatabaseMode=HYBRID | 有实测数据用实测插值，缺失回退 SOL × 经验系数，保证估算不中断 |
| GEMM / Attention / MoE 查表 | 按 `(M, N, K, dtype)` 多维线性插值 |
| AllReduce / NCCL 通信估算 | 按 `(tp_size, message_size)` 插值，覆盖 TP 同步与 MLA 的 AG+RS 模式 |
| SLA 校验 | `TTFT ≤ 1600 ms`、`TPOT ≤ 60 ms` |
| 显存 OOM 检查 | `weights/TP + activation + KV cache + HCCL ≤ 64 GiB`（Ascend 910B） |

#### M5 Pareto 选型

| 功能点 | 说明 |
|--------|------|
| batch / concurrency 扫描 | 在 `1..512` 范围扫描，找约束下的最大吞吐点 |
| SLA 硬过滤 | 剔除 `ttft > 1600` 或 `tpot > 60` 或 OOM 的候选 |
| Pareto 前沿提取 | 二维目标 `(tokens/s/user, tokens/s/gpu_cluster)` 的非支配点集 |
| pick_default | 固定 8 卡预算最大化吞吐；`top-n=10`，按并行组去重 |
| （可选）pick_load_match | `--target-concurrency` / `--target-request-rate` 下最小化 GPU 数 |

#### M6 结果输出与部署生成

| 功能点 | 说明 |
|--------|------|
| best_config_topn.csv | top-10 推荐配置表 |
| pareto.csv + pareto_frontier.png | 完整前沿点集 + 散点图 |
| exp_config.yaml | 可复现实验配置（`--mode yaml` 可直接重跑） |
| top1../top10/generator_config.yaml | 各推荐配置的部署生成配置 |
| backend artifacts | vLLM / dynamo 等后端可部署配置文件 |

### 2.2.3 default 模式支持 Qwen3-8B：命令拆解与能力说明

#### 命令示例

```bash
aic-npu default \
  --model-path /workspace/model_configs/qwen_3_8_config.json \
  --total-gpus 8 \
  --system ascend_910b \
  --backend vllm-ascend \
  --database-mode HYBRID \
  --isl 128 --osl 128 \
  --ttft 1600 --tpot 60 \
  --top-n 10 \
  --save-dir results
```

#### 参数逐项拆解

| 参数 | 值 | 作用 | 进入的模块 |
|------|-----|------|-----------|
| `--model-path` | `/workspace/model_configs/qwen_3_8_config.json` | Qwen3-8B 的 HF config.json，定义模型结构 | M2 |
| `--total-gpus` | `8` | GPU 预算=8 卡，裁剪并行搜索空间与集群折算 | M3 / M5 |
| `--system` | `ascend_910b` | 目标硬件=Ascend 910B（64GiB HBM / BF16 256TFLOPS） | M1 / M4 |
| `--backend` | `vllm-ascend` | 推理后端=vllm-ascend，决定调度步分解与算子数据目录 | M2 / M4 |
| `--database-mode` | `HYBRID` | 性能取数=实测优先 + SOL 兜底 | M4 |
| `--isl` | `128` | 输入序列长度 128 token（短序列/对话场景） | M4 |
| `--osl` | `128` | 输出序列长度 128 token | M4 |
| `--ttft` | `1600` | 首 token 延迟 SLA：**≤ 1600 ms** | M5 |
| `--tpot` | `60` | 每 token 延迟 SLA：**≤ 60 ms** | M5 |
| `--top-n` | `10` | 输出 top-10 最优配置（默认 5） | M5 / M6 |
| `--save-dir` | `results` | 结果输出根目录 | M6 |

#### 拆解能力

该命令在一次执行中完成以下完整拆解：

**1. 模型侧拆解**

- 读取 Qwen3-8B 结构参数（36 层 / hidden 4096 / GQA 32/8 / FFN 12288）
- 识别为 `LLAMA` dense 模型（非 MoE），自动标记 `use_qk_norm=True`
- 构建 prefill 与 decode 两套算子图，每层包含：Attention（QKV + Attn + Proj）+ FFN（Gate-Up + Act + Down）+ 2 次 TP AllReduce

**2. 硬件侧拆解**

- 加载 Ascend 910B 规格：64 GiB HBM、2 TB/s 带宽、BF16 256 TFLOPS、8 die/节点、HCCS 56 GB/s
- 加载 vllm-ascend 0.18.0 算子性能库（gemm / attention / moe / nccl 实测表）

**3. 搜索空间拆解**

| 维度 | 枚举值 | 候选数 |
|------|--------|--------|
| 并行配置 | TP∈{1,2,4,8}，PP=DP=1 | 4 |
| batch / concurrency | 1..512 | ~512 |
| tpot 网格 | 1..19 步1，20..295 步5 | ~70 |
| **合计候选点** | | **~数千** |

**4. SLA 与约束过滤**

- `ttft ≤ 1600 ms`（短 isl=128 场景下 prefill 较易满足）
- `tpot ≤ 60 ms`（decode 延迟约束，决定最大 batch）
- 显存 ≤ 64 GiB（OOM 剔除）

**5. 选型与输出**

- 在合法候选点上提取 Pareto 前沿（用户效率 vs 集群效率）
- `pick_default` 按 8 卡预算最大化吞吐，按并行组去重，输出 **top-10**
- 落盘全套结果与部署配置

#### 功能能力总结

| 能力 | 说明 |
|------|------|
| **模型自动识别** | 自动解析 HF config、映射架构族、识别 MoE/dense、处理 Qwen3 QK-Norm |
